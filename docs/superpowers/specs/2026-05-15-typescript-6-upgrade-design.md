# TypeScript 6 Upgrade — Design Spec

- **Status:** Approved (2026-05-15)
- **Author:** Developer (with Claude Opus 4.7)
- **Type:** Chore (dependency upgrade) — not a BUILD_GUIDE phase
- **Related ADRs:** 0013 (created as part of this chore)
- **Implementation plan:** `docs/superpowers/plans/2026-05-15-typescript-6-upgrade-plan.md` (to be written next)

---

## 1. Goal

Bump `typescript` from `^5.6.3` to `^6.0.0` with zero behavior changes. The previous Dependabot attempt (PR #41, closed) failed because TS 6 raises `error TS5101` on `tsconfig.app.json`'s `"baseUrl": "."` line. With the fix in place, the upgrade should be mechanical.

This is a chore, not a feature. No version tag, no GitHub release. CHANGELOG entry under `[Unreleased]`.

## 2. Non-goals

- TypeScript-eslint version bump (already at v8.x, which supports TS 6).
- Vite or Vitest version bumps (separate Dependabot PRs, separate decisions).
- Strictness changes to `tsconfig.app.json` beyond removing `baseUrl`.
- Any source-code refactor beyond what TS 6 forces.

## 3. Decisions made

| #   | Decision                                                                                              | Rationale                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Remove `"baseUrl": "."` from `tsconfig.app.json`; rely on `paths` alone                               | TS 6 errors on `baseUrl`; with `moduleResolution: "bundler"` the `paths` map resolves correctly without it (verified in TS 5+ docs). |
| 2   | Single PR `chore/typescript-6-upgrade`                                                                | Mechanical change, small surface, no test changes expected.                                                                          |
| 3   | If TS 6 surfaces additional breaking changes (stricter type narrowing, etc.), fix them in the same PR | Avoids partial-upgrade limbo. Each fix gets its own commit so review can isolate.                                                    |
| 4   | No release tag                                                                                        | Chore, not a feature. CHANGELOG `[Unreleased]` entry only.                                                                           |

## 5. Required changes

### 5.1 `tsconfig.app.json`

Remove the `baseUrl` line. Resulting `compilerOptions` excerpt:

```json
{
  "moduleResolution": "bundler",
  "paths": { "@/*": ["src/*"] }
}
```

`paths` resolves relative to the location of the tsconfig file when `baseUrl` is absent (TS 4.1+).

### 5.2 `package.json`

Bump `typescript` to `^6.0.0` (or whatever is the latest 6.x at execution time, e.g. `^6.0.3`).

### 5.3 `pnpm-lock.yaml`

Auto-regenerated by `pnpm install`.

### 5.4 ADR-0013

Create `docs/adr/0013-typescript-6-upgrade.md`:

```markdown
# ADR-0013: TypeScript 6 upgrade — drop `baseUrl`

- Status: Accepted
- Date: 2026-05-15
- Deciders: Developer

## Context

Dependabot opened a PR bumping TypeScript from 5.x to 6.0.3, which failed CI
because TS 6 raises `error TS5101` on `tsconfig.app.json`'s `"baseUrl": "."`
line. We previously closed that PR (#41) and noted the migration as a follow-up.

## Decision

Remove `baseUrl` from `tsconfig.app.json`. The `paths` map (`{ "@/*":
["src/*"] }`) resolves relative to the tsconfig location when `baseUrl` is
absent (TS 4.1+). With `moduleResolution: "bundler"` already in place, no
other config change is required.

Bump `typescript` to `^6.0.0`.

## Alternatives considered

- **Keep `baseUrl: "."`**: not possible — TS 6 errors out.
- **Replace `paths` with explicit per-import relative paths**: defeats the
  purpose of the alias and forces a sweep of every import.
- **Stay on TS 5**: postpones the inevitable; not bad short-term but accumulates
  drift. Dependabot will keep nagging.

## Consequences

- One-line tsconfig change.
- Existing `@/*` imports continue to resolve.
- typescript-eslint 8.x already supports TS 6 — no parser bump needed.
- If TS 6 surfaces other strictness changes (e.g. tighter narrowing in
  generics), they're addressed in the same PR.

## References

- TypeScript 5.0 release notes (`baseUrl` becomes optional with `paths`).
- TypeScript 6.0 release notes (`baseUrl` raises TS5101).
- ADR-0001 (broader stack — TS is the chosen language).
```

## 6. Test plan

Mechanical verification only — no new tests:

| Check                                                   | Expected                                                         |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| `pnpm install --frozen-lockfile` (after lockfile regen) | succeeds                                                         |
| `pnpm typecheck`                                        | exits 0 (all 11 source files + 11 test files compile under TS 6) |
| `pnpm lint`                                             | exits 0 (typescript-eslint 8.x parses TS 6 source)               |
| `pnpm test:run`                                         | 59/59 tests pass                                                 |
| `pnpm build`                                            | exits 0; Vite produces `dist/`                                   |
| `pnpm format:check`                                     | exits 0                                                          |

**Risk surface:** TS 6 may have stricter inference in places where we use:

- Generics with conditional types (none in our code currently).
- `unknown` narrowing (one usage in `auth.ts`'s `isUniqueIndexError` — already cast through `Record<string, unknown>`).
- `noUncheckedIndexedAccess` interactions (we use `[i]!` non-null assertions in `crypto.ts` and `avatar.ts` — should still work).

If `pnpm typecheck` fails on something unexpected, fix it in the same PR with a separate commit and a one-line explanation in the commit body.

## 7. PR plan

### Single PR — `chore/typescript-6-upgrade`

**Branch:** from `main`.

**Commits (logical chunks):**

1. `chore(repo): drop baseUrl from tsconfig.app.json (prep for TS 6)` — tsconfig change only. Verify `pnpm typecheck` still passes on TS 5.6 to prove it's a no-op on the current version.
2. `chore(deps-dev): bump typescript from 5.6.x to 6.x` — package.json + lockfile.
3. `docs(adr): ADR-0013 TypeScript 6 upgrade` — ADR file.
4. (Conditional) one commit per additional TS 6 fix, if any.

**CI:** the standard 4 jobs (meta, lint, test, build) must all pass before merge.

**CHANGELOG:** add to `[Unreleased]` section:

```markdown
### Changed

- TypeScript bumped from 5.6 to 6.x. Dropped `baseUrl` from `tsconfig.app.json` (TS 6 raises TS5101). `paths` alias resolves the same way without it. ADR-0013.
```

(The CHANGELOG entry can be in commit #2 or its own commit — author's choice.)

## 8. Definition of Done

- [ ] `tsconfig.app.json` has no `baseUrl` line; still has `paths: { "@/*": ["src/*"] }`.
- [ ] `package.json` shows `"typescript": "^6.x.y"`.
- [ ] `pnpm install --frozen-lockfile` succeeds on a clean clone.
- [ ] All four CI jobs pass on the PR.
- [ ] PR merged to `main` via `--squash --delete-branch`.
- [ ] ADR-0013 present and Accepted.
- [ ] CHANGELOG `[Unreleased]` mentions the upgrade.

## 9. Rollback procedure

If TS 6 surfaces a problem post-merge that wasn't caught by CI:

```bash
git revert <merge-commit> -m 1
git push origin main
```

The lockfile pinning to TS 6 reverts with it; `pnpm install --frozen-lockfile` returns the workspace to TS 5.
